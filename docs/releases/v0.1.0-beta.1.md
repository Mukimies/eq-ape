# EQ Ape 0.1.0-beta.1 (pre-release)

EQ Ape is a menu bar equalizer for macOS that processes all system audio going to your output device, without a virtual audio driver (it uses Core Audio process taps). It reads Equalizer APO-style configuration files, so parametric EQ and room-correction text files (including REW exports) can be loaded directly.

This is an early beta. It is **source-available** (Apache-2.0 with the Commons Clause), not open source.

This build includes the configuration editor (frequency-response graph, filter sliders, live save with backups and undo), the Settings window and the first-run window.

- **Variable graphic EQ:** GraphicEQ lines are edited like Equalizer APO's Graphic EQ: each row has its own graph of numbered nodes with a power toggle and a 15-band / 31-band / variable choice. In variable mode nodes move sideways and vertically and can be added (double-click) and removed; the selected line's nodes can also be dragged on the main graph. A vertical-slider sheet remains. "Add" offers variable, 15-band and 31-band graphic EQ lines. Only rendered and driven by a scripted test so far, not yet used by a person.
- **Anti-clipping counts every filter:** the automatic gain now includes high-pass, low-pass and other filters (and resonant peaks) and the graphic EQ's real response, so a bass boost under a high-pass no longer makes the EQ quieter than needed (example: -10.69 dB became -9.41 dB). It keeps a steady full-scale tone below 0 dBFS minus the headroom; short peaks of loud, already-limited music can still clip by a few dB because of phase shifts, which the clip light shows.

## Requirements

- macOS 14.2 or later
- Apple Silicon (arm64). There is no Intel or universal build.

## This build is not notarized

This release is ad-hoc signed and **not notarized by Apple**. There is no Apple Developer ID behind it. macOS will refuse to open it at first, and the audio-capture permission will probably have to be granted again after each update (the grant is tied to the exact build; not verified).

## Install

1. Download `EQ-Ape-{{VERSION}}.dmg` and `EQ-Ape-{{VERSION}}.dmg.sha256` from this release. Verify:
   `shasum -a 256 -c EQ-Ape-{{VERSION}}.dmg.sha256`
2. Open the DMG and drag **EQ Ape** to Applications.
3. Double-click EQ Ape. macOS shows an alert that it cannot verify the app. Close it (do not move the app to the Trash).
4. Open System Settings > Privacy & Security, scroll to the Security section, click **Open Anyway** next to the EQ Ape message and confirm. The button is reported to stay available for about an hour after the failed launch; if it has vanished, double-click the app again.
5. Command-line alternative: `xattr -dr com.apple.quarantine "/Applications/EQ Ape.app"`.

Control-click > Open no longer bypasses Gatekeeper on macOS 15 and later. The exact wording varies between macOS versions and was not tested on every version. Building from source yourself avoids the quarantine step (see the README).

## First run

1. Start EQ Ape. It appears in the menu bar (no Dock icon).
2. macOS asks for the **audio capture** permission the first time EQ Ape starts processing. **Answer the prompt promptly.** An unanswered prompt can stall new audio for every app on the Mac until it is answered. Already-running audio keeps playing. This is not a microphone permission, but on a device that has inputs a Microphone prompt may appear as well (untested for the shipped app).
3. Choose a config file for your output device from the menu ("Choose Config File..."). Profiles are kept per output device.

## What has been checked, and what has not

Taken from `docs/APP-NOTES.md` and `docs/TAP-FINDINGS.md`.

Checked:
- The tap engine was measured on a Scarlett Solo USB and on MacBook Pro Speakers: real audio, processing applied, no overloads or timestamp discontinuities, about 23-24 ms added delay.
- The app logic (per-device profiles, following the default output, live config reload, sample-rate change, a 5-minute soak, recovery after `kill -9`) was exercised through the app's headless mode. Edit-to-new-EQ time was 0.34-0.36 s.
- The DSP and config parser are covered by automated tests (including a parity audit against Equalizer APO's documented behaviour).

Not checked:
- Muting of the original sound on anything other than a Scarlett Solo USB (confirmed by ear there with the first menu-bar build: EQ engaged, no doubling). This needs listening on each setup.
- The configuration editor (including graphic EQ node editing) has had only a brief hands-on try by the author with the engine running, on one setup; individual controls (keyboard handling, reordering, mode conversion, the Settings and first-run windows) have not been checked one by one. Beyond that it was rendered offscreen, inspected, and driven by a scripted smoke test without the engine (see `docs/EDITOR-NOTES.md`).
- Bluetooth, AirPlay and HDMI outputs; unplug/replug and sleep/wake; runs longer than five minutes.
- Whether the audio-capture permission survives updates of an ad-hoc signed build.
- Whether the audio-input entitlement is needed under the hardened runtime.

## Known issues

- With a device that has inputs, the aggregate device still contains them, which may cost a Microphone prompt.
- Switching devices leaves a gap of about 0.3-0.9 s in which audio plays unprocessed on the new device.
- System alert sounds go to the "system output" device, which is not tapped unless it is the same as the default output.
- `settings.json` is read at launch; external edits while the app runs are not picked up (config files are).
- Unsupported Equalizer APO lines (`Device:`, `Stage:`, `Copy:`, `Delay:`, `Convolution:`, `Eval:`, `If:` blocks, `LoudnessCorrection:`, `VSTPlugin:`, `Filter: ON IIR`) are ignored with a warning; see `docs/APO-PARITY.md`.

## Privacy

Audio is processed in memory only and never written to disk or sent anywhere. The app makes no network connections and has no update checker.
